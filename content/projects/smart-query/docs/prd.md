# 智能问数 Agent 产品需求文档（PRD）

| 项目 | 内容 |
| --- | --- |
| 产品 | 智能问数 Agent（NL2SQL） |
| 负责人 | 石浩田 · AI 产品经理 |
| 阶段 | 招商金科 · 2026.03—2026.06 |
| 版本 | v1.0（脱敏版） |

> 作品集展示用。生产系统、数据与账号属于招商金科内部资产；用户画像来自岗位职责与流程观察，不虚构访谈，试点规模标注「目标/假设」。

## 1. 背景

业务取数依赖数据开发排期：提需求、转译、排队、写 SQL、回传、复核，一次临时分析平均约 **6 小时**。写 SQL 只占一小部分，大量时间耗在等待和澄清；数据开发则被重复需求挤占。

更深层的矛盾是：**报表预定义，问题却临时长出来**；**指标平台有口径，业务却不会把口语映射成字段**；**想自助，又怕权限、脱敏和误操作失控**。通用 Chatbot 能生成 SQL，却不懂企业 Schema、口径和数据坑，答案看似合理却不可信。

产品假设：在数仓与业务之间补一层「受约束的问数能力」——用语义资产解决找不对数，用 Agent 解决不会拆问题，用安全护栏解决不敢放开。

## 2. 用户与场景

| 角色 | 特征 | 诉求与痛点 | 成功标准 |
| --- | --- | --- | --- |
| 业务分析师 P1 | 会 Excel，不写 SQL | 临时取数、对比、做汇报；等数久、口径反复问 | 一次对话拿到可用的表和图 |
| 条线负责人 P2 | 关注异动，时间碎片化 | 快速追问「为什么、哪家、趋势」；只能看固定报表 | 2—3 轮追问得到可解释结论 |
| 数据开发 P3 | 维护 ETL 与宽表 | 减少重复接单；需求不清、反复返工 | 系统挡掉标准问题，并沉淀语义资产 |

> 假设画像，需在灰度中用真实提问、采纳率与访谈校准。核心场景：快查、环比/同比、维度归因、口径确认、脱敏导出（P0）；数据探查（P1）。

**JTBD**：我需要数据支撑判断时，想直接问清楚，并知道数来自哪张表、什么口径、是否可信，不用等排期，也不担心用错。

## 3. 竞品与替代方案

| 方案 | 优势 | 关键缺陷 | 我们的位置 |
| --- | --- | --- | --- |
| 传统 BI/报表 | 口径稳定、可视化与权限成熟 | 只覆盖已定义问题；临时需求仍要排期 | 不替代 BI，做临时问题前置入口 |
| 通用 Chatbot | 自然语言体验好、上手快 | 不懂 Schema，易编表编字段；无权限审计 | 用 evidence 约束生成，只读执行 |
| 单点 NL2SQL 工具 | 能生成 SQL，接入看似简单 | 假设 Schema 干净；缺业务解释、指标与安全 | 四层语义 + 混合检索 + 路由 + 评测 |
| 数据开发排期 | 准确、有人负责 | 慢、沟通成本高、无法自助 | 消化标准问题，人工处理长尾 |
| 本产品 | 快、可解释、受控、可评测 | 依赖语义覆盖；复杂归因有限 | 问数前置层，不是万能分析师 |

结论：不与 BI 争固定报表，不与 Chatbot 争闲聊，不与数据开发争复杂建模。只吃「高频标准、临时对比、语义已覆盖的多步问题」，超出范围交回人工，比强行答错更专业。

## 4. 目标与非目标

**目标**：把临时取数等待从小时级压到分钟级；让不会 SQL 的业务完成「提问—取数—看图—追问」；正确率 ≥85%、高危拦截 100%、P95 <60 秒；沉淀语义资产与评测方法。

**非目标**：不做写操作与 ETL；不做开放域问答；不替代 BI 与指标平台；不做因果推断；V1 不做跨域任意 join、不做无审批导出。

## 5. 指标与口径

| 指标 | 口径 | 目标 | 当前状态 |
| --- | --- | --- | --- |
| 答案正确率 | 评测集上 SQL 执行结果与标准结果一致；按题计分，错一题不得分 | ≥ 85% | **85%+，已达成** |
| 任务完成率 | 有效提问中获得可采纳结果（复制/导出/点赞/无重复改写）的会话占比 | ≥ 75% | 试点观察，目标 |
| 自助率 | 无需数据开发介入的提问数 / 有效提问数 | ≥ 60% | 目标/假设 |
| 端到端 P50 | 发送问题到答案返回，含检索、生成、执行、渲染 | ≤ 30 秒 | **30 秒级，已达成** |
| 端到端 P95 | 同上，95 分位 | < 60 秒 | 待压测，目标 |
| 安全拦截率 | 既定攻击/越权/高危用例被阻断的比例 | 100% | **100%，规则覆盖内** |
| 澄清命中率 | 发起澄清后用户给出有效口径的比例 | ≥ 90% | 目标 |
| 数据开发介入率 | 仍需人工接单的提问占比 | 下降 50% | 目标/假设 |

口径说明：

- 正确率用 execution accuracy，不比对 SQL 文本；业务方与数据开发双人标注，争议题复核。
- 「6 小时 → 30 秒」不是同一段操作：6 小时含转译、排期、回传、复核；30 秒是系统链路 P50，不含人审。90% 是业务自报端到端降幅，灰度样本有限；三个数字必须带分母。
- 85% 是灰度问题分布下的结果，复杂多表与长尾会低于均值；安全用例只统计确定性规则可判定的部分。

## 6. 功能模块

### M1 登录与数据域（P0）

对接统一登录，会话绑定工号、组织、角色、数据域；请求进入模型前注入 `user_scope`；未登录、过期、跨域访问拒绝并审计。

### M2 对话工作台（P0）

支持多轮追问、指代消解与条件继承（「那按机构拆呢」）；展示「理解→找数→生成→校验→执行→整理」状态；失败给可操作建议而非只报错。

### M3 语义资产与四层准备（P0）

1. **L1 元数据**：表/字段注释、类型、枚举、空值率、脏数据说明、敏感级别。
2. **L2 关系**：主外键、join 键、桥表、粒度、渠道/机构/产品编码对齐。
3. **L3 业务解释**：一行数据代表什么、时间语义、业务规则、同义词、常见误区。
4. **L4 指标**：定义、公式、维度、排除项、负责人、版本、血缘。

语义卡带版本与负责人；L1 脏数据说明必须具体，不能写「质量一般」。

### M4 混合检索与 Schema Linking（P0）

向量 + 倒排双路召回，RRF 融合重排，输出表、字段、指标、同义词、关系五类证据；先做时间/别名/机构归一化；Schema Linking 给出候选、join、粒度冲突与置信度，低置信不硬猜；证据以 `[E1]…[En]` 注入，SQL 必须可追溯。

### M5 复杂度路由与 Agent（P0）

- **简单**：单表单指标、无歧义 → few-shot 改写 + 单次 SQL。
- **中等**：2—4 表、多指标、环比 → Decomposition + CoT，拆 2—4 个子问题。
- **复杂**：多步归因、跨域、需工具观察 → ReAct Loop，最多 4 轮、6 次工具调用。
- **澄清/拒绝**：口径多解先问；越权、写操作、域外直接拒绝。

工具固定为 `search_schema`、`get_metric`、`validate_sql`、`run_sql_readonly`、`make_chart`、`ask_user`；每轮观察写入 trace，不允许无限循环。

### M6 SQL 生成、校验与修复（P0）

生成时输出 SQL、表/字段、指标 ID、假设、置信度；Checker 检查存在性、join、公式、时间边界、聚合、分区、权限、除零；AST 只允许单条 SELECT/CTE；自动 LIMIT 1000、超时与扫描量上限；Repair 最多 2 轮，只做最小修复，不得删业务过滤；仍失败给错误分类与建议。

### M7 安全与合规（P0）

只读账号 + AST 拒绝写操作；强制分区过滤、LIMIT、超时；数据域 + 行级组织过滤 + 列级权限；敏感字段默认脱敏，日志不落明文；导出审批、水印、行数上限与审计；用户文本视为数据而非指令，系统提示不可回显。

### M8 结果呈现与导出（P0/P1）

固定结构：结论 → 关键数字 → 数据表 → 图表 → 口径/假设 → 折叠 SQL；图表按时间折线、类别柱状、占比饼图（≤6 类）、单值 KPI 选型，类别 >12 回退表格；数字只来自结果集，展示单位、时间范围与数据截止时间；导出前提示敏感字段并留痕。

### M9 评测与运营（P0）

评测集覆盖简单/中等/复杂、歧义、空结果、越权、攻击、脏数据；改 Prompt、换模型、补语义卡都跑回归，正确率降超 2 个百分点或安全失败即阻断发布；线上反馈进入周度归因，缺口回流语义层。

## 8. 灰度与迭代

| 阶段 | 时间（复盘口径） | 内容 | 退出条件 |
| --- | --- | --- | --- |
| P0 语义冷启动 | 2026.03—04 | 接入 10+ 个真实 ETL 脚本、近千字段；补表卡、关系、同义词、指标卡 | 核心域可检索，覆盖试点要求 |
| P1 离线评测 | 2026.04 | 分层评测集、baseline、错误归因、修 Schema Linking/Prompt | 正确率 ≥ 85%，安全全过 |
| P2 Shadow | 2026.05 | 真实问题影子运行，对比标准 SQL，记录时延与失败 | 连续两周稳定，无 P0 事故 |
| P3 试点 | 2026.05—06 | 某业务条线试用，收集采纳、追问、报错，每周补语义卡 | 任务完成率/自助率达试点目标 |
| P4 扩展 | 2026.06 后 | 复制到第二、三个数据域，补复杂分析 | 新域不低于首域，成本可控 |

节奏：每周补语义 + 回归，每两周策略对比，每月安全演练。灰度期最重要的不是加功能，而是把错误变成可复用的语义资产。

## 9. 风险与依赖

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 语义覆盖不足 | 长尾答不了 | 先做高频域；明确不支持；缺口进待办 |
| 模型幻觉/编字段 | 答案似真但错 | evidence 约束、Schema 校验、Checker、拒答 |
| 口径冲突 | 同一指标多个数 | 指标平台唯一源；冲突澄清；禁止自创公式 |
| 权限配置错误 | 越权或过度收敛 | 行级规则双人复核、对账、安全回归 |
| 复杂问题能力不足 | 归因体验差 | 限定边界；下钻+相关；转人工 |
| 性能/成本 | 复杂问题慢且贵 | 路由、缓存、上下文裁剪、修复上限 |
| 业务不信任 | 仍走人工 | 展示 SQL/口径/证据；先辅助再自动 |
| 数据新鲜度 | 用旧数据判断 | 展示截止时间；延迟告警；时效提示 |

关键依赖：统一登录与组织、指标平台口径、数仓只读账号与权限、模型网关、审计平台；任一缺失都会压缩能力边界。
